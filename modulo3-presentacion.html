2 · subir_repo

Script o función: dos formas de guardar comandos

Script

Un archivo guardado en una carpeta.

# archivo hola.sh (se escribe en nano)
#!/bin/bash
echo "Hola"
$ chmod +x hola.sh
$ ./hola.sh       # por su ruta

Función

Un comando con nombre que vive dentro de tu terminal.

# se escribe en la terminal o en ~/.zshrc
hola() {
  echo "Hola"
}
$ hola            # por su nombre
ScriptFunción
¿Cómo la usas?Escribes su ruta: ./subir.shEscribes su nombre: subir_repo
¿Desde dónde?Desde su carpeta (o con la ruta completa)Desde cualquier carpeta
¿Necesita chmod +x?SíNo
Parecido a…Un programa que abresUn comando como ls o cd

2 · subir_repo

¿Por qué subir_repo es una función?

Porque la usas dentro de cada repo, y cada repo está en una carpeta distinta. Un repo es solo una carpeta que tiene Git; la función se puede llamar desde cualquier carpeta.

Si fuera un script ✗ 
~/
├── mis-scripts/
│   └── subir.sh   ← vive aquí
├── repo-a/     ← trabajas aquí
└── repo-b/
~/repo-a$ ./subir.sh archivo
no such file or directory: ./subir.sh
~/repo-a$ ~/mis-scripts/subir.sh archivo   # ruta larga
Como función ✓ 
~/
├── repo-a/     ← funciona aquí
└── repo-b/     ← y aquí
~/repo-a$ subir_repo archivo
~/repo-b$ subir_repo archivo
La función vive en tu terminal, no en una carpeta: la llamas por su nombre desde donde estés, igual que ls.

2 · subir_repo

La función, línea por línea

1subir_repo() {
2 git add "$@"
3 git commit -m "Actualización: $*"
4 git push
5}
NombreAsí se llamará tu comando. Los () dicen “es una función”.
$@Las palabras que escribes después de subir_repo: git add las toma como archivos.
$*Las mismas palabras, juntas en el mensaje del commit.
pushLo manda a GitHub.
FinLa llave } cierra la función.

Lo de adentro de { } son los mismos 3 comandos de siempre. El mensaje siempre dirá “Actualización: …”; para cambiarlo, editas ese texto en la función.

2 · subir_repo

¿Dónde vive la función? En ~/.zshrc

Si la escribes directo en la terminal, se pierde al cerrarla. Por eso se guarda en un archivo oculto que la terminal lee cada vez que se abre.

1 · Abres la terminalSe enciende vacía.
→
2 · Lee ~/.zshrcconfiguraciónArchivo oculto en tu carpeta personal.
→
3 · Carga subir_repoLa función queda lista en memoria.
→
4 · La usassubir_repo …En cualquier carpeta.

¿Cómo se guarda ahí?

Es un archivo de texto: lo abres con nano, pegas la función al final y guardas.

¿Y si cierro la terminal?

La función se borra de esa ventana, pero la próxima terminal la vuelve a leer de ~/.zshrc.

¿Qué archivo?

Kali (zsh): ~/.zshrc
Ubuntu (bash): ~/.bashrc

2 · subir_repo

Instálala: 4 pasos (solo una vez)

1 · Abre tu configuración Desde cualquier carpeta: ~ siempre es tu carpeta personal.
$ nano ~/.zshrc       # Ubuntu: nano ~/.bashrc
2 · Baja al final y pega 
subir_repo() {
  git add "$@"
  git commit -m "Actualización: $*"
  git push
}
Guarda con Ctrl + O y Enter; sal con Ctrl + X.
3 · Cárgala ahorasource = “lee este archivo ahora”. Sin esto, tendrías que cerrar y abrir la terminal. 
$ source ~/.zshrc
4 · Comprueba que existe 
$ type subir_repo
subir_repo is a shell function

3 · el reto · paso 2

Escribe tu script: nano estructura.sh

Cada quien lo escribe en nano, bloque por bloque. Cambia Tu Nombre por el tuyo.

Bloque 1 · Prepara
#!/bin/bash
# estructura.sh: crea un proyecto
PROYECTO="$1"
→ Bash sabrá ejecutarlo y guarda el nombre que escribas (mi-app).
Bloque 2 · Crea carpetas y archivos
mkdir -p "$PROYECTO/src" "$PROYECTO/docs" "$PROYECTO/img"
touch "$PROYECTO/src/main.sh"
touch "$PROYECTO/docs/.gitkeep" "$PROYECTO/img/.gitkeep"
→ mi-app/src/main.sh, mi-app/docs/, mi-app/img/. Los .gitkeep sirven para que GitHub muestre las carpetas vacías.
Bloque 3 · Escribe el README y avisa
echo "# $PROYECTO" > "$PROYECTO/README.md"
echo "Hecho por: Tu Nombre" >> "$PROYECTO/README.md"
echo "Proyecto $PROYECTO creado"
→ mi-app/README.md con el título y tu nombre, y un mensaje al terminar.

3 · el reto · tu parte

Tu parte: agrega una carpeta y una subcarpeta

Agrega a tu script una carpeta al mismo nivel que src, docs e img, con una subcarpeta adentro. El tema lo eliges tú: tu escuela, animales, música…

Agrega esta línea a tu script 
mkdir -p "$PROYECTO/escuela/tareas"
touch "$PROYECTO/escuela/tareas/.gitkeep"
Cambia escuela/tareas por tu tema. El .gitkeep hace que GitHub muestre la carpeta.
Así quedaría
mi-app/
├── README.md
├── src/
│   └── main.sh
├── docs/
├── img/
└── escuela/     ← nueva
    └── tareas/  ← nueva

3 · el reto

¿Cómo se evalúa?

  • El repositorio es público y el link funciona
  • estructura.sh empieza con #!/bin/bash y tiene un comentario
  • Usa una variable (o $1) para el nombre del proyecto
  • Crea al menos 3 carpetas con mkdir -p y un archivo con touch
  • Crea un README.md con título y tu nombre usando > y >>
  • La estructura creada también está subida al repo
