1 · permisos

Permisos: se leen en bloques de 3 letras

-tipo- archivo · d carpeta
rwxdueñotú
r-xgrupotu grupo de usuarios
r-xotrostodos los demás

Siempre van en orden r w x. Cuando vuelve a aparecer una r, empieza el siguiente grupo. Un - significa “no tiene ese permiso”.

LetraEn un archivoEn una carpeta
rVer su contenido (cat)Ver qué hay adentro (ls)
wModificarlo (echo >)Crear o borrar cosas adentro
xEjecutarlo como programaEntrar (cd)

1 · permisos

chmodDar (+) o quitar (-) permisoschange mode
dueñogrupootros
comandoantesdespués
chmod +x saludo.txtagrega x a los tres grupos
-rw-r--r-- saludo.txt
→
-rwxr-xr-x saludo.txt
chmod -x saludo.txtquita x a los tres grupos
-rwxr-xr-x saludo.txt
→
-rw-r--r-- saludo.txt

Sin letra antes del + o -, el cambio se aplica a los tres bloques. Si un bloque ya tenía la x, se queda igual.

Funciona con cualquier letra: +r -r +w -w +x -x. Con x, ls lo pinta de verde.

2 · bash scripting

¿Qué es un script y para qué sirve?

Un archivo .sh con comandos guardados. La terminal los ejecuta uno por uno, de arriba hacia abajo.

Sin script: lo escribes a mano cada vez 
$ mkdir -p proyecto/src proyecto/docs
$ touch proyecto/src/main.sh
$ echo '# Mi proyecto' > proyecto/README.md
Con script: un solo comando 
$ ./nuevo_proyecto.sh
nuevo_proyecto.sh1 · mkdir -p ...2 · touch ...3 · echo ...
⟶se ejecutan
en orden
Resultado✓ carpetas✓ archivo✓ README

3 · tu propio comando

Funciones: un comando con nombre, hecho por ti

escríbela directo en la terminal
saludar() {
  echo "Hola $1"
}
úsala como cualquier comando
$ saludar Ana
Hola Ana
$ saludar Curies
Hola Curies

¿Dónde se escribe? Directo en la terminal, no en un script ni en nano. Escribe la primera línea, Enter, la del medio, Enter, y la llave }, Enter. Ya queda lista para usarse.

nombre()El nombre de tu comando, con paréntesis vacíos.
{ ... }Adentro, los comandos que va a ejecutar.
OjoSi cierras la terminal, la función se pierde. Siguiente: guardarla.

3 · tu propio comando

Tu comando subir_repo: add + commit + push en uno

al final de ~/.zshrc (Kali) o ~/.bashrc (Ubuntu)
subir_repo() {
  git add "$@"
  git commit -m "Actualización: $*"
  git push
}
  1. nano ~/.zshrc (Kali) o nano ~/.bashrc (Ubuntu)
  2. Baja hasta el final, pega la función, guarda y sal
  3. Carga los cambios: source ~/.zshrc
  4. Entra a tu repo y úsalo: subir_repo README.md
~/mi-repo$ subir_repo README.md
[main 1c0d7fe] Actualización: README.md
 1 file changed, 1 insertion(+)
To https://github.com/tu-usuario/mi-repo.git

$@ = los archivos que escribes · $* = esos mismos nombres, en el mensaje del commit · source = vuelve a leer tu configuración

reto · módulo 3

El reto del miércoles

Crea un script estructura.sh que arme un proyecto, y súbelo a tu repositorio público con tu comando subir_repo.

  1. Empieza con #!/bin/bash y tiene al menos un comentario
  2. Usa una variable (o $1) para el nombre del proyecto
  3. Crea al menos 3 carpetas con mkdir -p y un archivo con touch
  4. Crea un README.md con título y tu nombre usando echo > y >>
  5. Lo subes con subir_repo y compartes el link de tu repo

Requisito: tu cuenta de GitHub y un repositorio público tuyo. Se evaluará con ese link.
